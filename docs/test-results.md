# 試験結果

## 1. 試験概要

Cisco Packet Tracer上で構築したMulti-AS BGP環境について、以下を確認した。

- BGPネイバー確立
- 複数BGP経路の学習
- ベストパス選択
- PC間疎通
- リンク障害時の経路切り替え
- リンク復旧後のBGPネイバーおよび経路復旧

## 2. BGPネイバー確認

### R1

`show ip bgp summary` を実行し、以下のネイバーとのBGPセッション確立を確認した。

| Neighbor | Remote AS | 結果 |
|---|---:|---|
| 10.0.12.2 | 65002 | Established |
| 10.0.13.2 | 65003 | Established |

R1はR2およびR3の両方とeBGPネイバーを確立していることを確認した。

## 3. BGP経路確認

R1で `show ip bgp` を実行した。

192.168.40.0/24に対して以下の2経路を学習した。

```text
*> 192.168.40.0/24   10.0.12.2   65002 65004 i
*                    10.0.13.2   65003 65004 i
```

通常時はR2経由の経路がベストパスとして選択された。

```text
R1 -> R2 -> R4
```

AS_PATH:

```text
65002 65004
```

R3経由の経路も有効な代替経路としてBGPテーブルに保持されていることを確認した。

```text
R1 -> R3 -> R4
```

AS_PATH:

```text
65003 65004
```

## 4. ルーティングテーブル確認

R1で `show ip route bgp` を実行した。

通常時は以下のBGP経路がルーティングテーブルに登録されていた。

```text
B 192.168.40.0/24 [20/0] via 10.0.12.2
```

192.168.40.0/24への通信でR2をNext Hopとして使用していることを確認した。

## 5. 障害試験

### 試験内容

R1のGigabitEthernet0/1をshutdownし、R1-R2間リンクを停止した。

```text
R1(config)# interface GigabitEthernet0/1
R1(config-if)# shutdown
```

### BGP経路切り替え確認

障害発生後、R1で `show ip bgp` を実行した。

```text
*> 192.168.40.0/24   10.0.13.2   65003 65004 i
```

R2経由の経路が消失し、R3経由がベストパスへ切り替わったことを確認した。

障害時経路:

```text
R1 -> R3 -> R4
```

また、`show ip route bgp` で以下を確認した。

```text
B 192.168.40.0/24 [20/0] via 10.0.13.2
```

ルーティングテーブル上でもNext HopがR3に変更されていることを確認した。

## 6. 障害時疎通確認

R1-R2間リンク停止中にPC1からPC2へpingを実行した。

```text
ping 192.168.40.10
```

結果:

```text
Packets: Sent = 4, Received = 4, Lost = 0 (0% loss)
```

R1-R2間リンク障害中でも、R3経由でPC1からPC2への通信が継続できることを確認した。

## 7. リンク復旧試験

R1のGigabitEthernet0/1をno shutdownし、R1-R2間リンクを復旧した。

```text
R1(config)# interface GigabitEthernet0/1
R1(config-if)# no shutdown
```

復旧後、R1で再度 `show ip bgp` を確認した。

```text
*> 192.168.40.0/24   10.0.13.2   65003 65004 i
*                    10.0.12.2   65002 65004 i
```

R2経由およびR3経由の両方のBGP経路が再度学習されたことを確認した。

今回はR2経由を明示的に優先するBGPポリシーを設定していないため、リンク復旧後もR3経由がベストパスとして継続して選択された。

## 8. BGPネイバー復旧確認

リンク復旧後、`show ip bgp summary` を実行した。

```text
Neighbor        AS      Up/Down
10.0.12.2       65002   00:00:58
10.0.13.2       65003   00:06:13
```

R2およびR3とのBGPセッションが正常に確立していることを確認した。

R2とのセッションはリンク復旧後に再確立されたため、R3とのセッションよりUp/Down時間が短くなっている。

## 9. 試験結果まとめ

| 試験項目 | 結果 |
|---|---|
| BGPネイバー確立 | OK |
| 複数経路学習 | OK |
| BGPベストパス選択 | OK |
| 通常時PC間疎通 | OK |
| R1-R2リンク障害時の経路切り替え | OK |
| 障害時PC間疎通 | OK |
| リンク復旧後のBGP経路復旧 | OK |
| BGPネイバー再確立 | OK |

Multi-AS環境において、eBGPによる経路交換、複数経路の保持、ベストパス選択、リンク障害時の経路切り替えおよび通信継続を確認できた。
